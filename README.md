# 文档知识库问答（python-doc-rag）

基于本地文档的**检索增强生成（RAG）**问答应用：把一批 `.txt` 文档切片、向量化建库，
用中文提问后，系统从文档中检索相关片段、由大模型生成答案，并标注答案来源（可追溯、防幻觉）。

本仓库是 `course-rag` 的**作品集化版本**：数据换成公开的 **Python 官方教程**（tutorial 章节，中英两版各 17 个 `.txt`），
不含任何私有课件，可直接对外展示 / 部署 / 面试演示。

## 功能

- 预置知识库：一键扫描语料目录下全部 `.txt` 建库（中文版与英文版各一套，见「数据说明」）
- 增量上传：界面上传 `.txt`，追加进当前知识库
- 带引用问答：检索片段送入模型前即拼接 `[来源:文件名]`，模型"看得到"真实出处，答案可追溯
- 拒绝回答：库外问题明确说"文档中未找到相关信息"，不硬编、不把无关片段当依据
- 网页界面：Streamlit，浏览器打开即用

## 技术栈

| 环节 | 选型 | 说明 |
|------|------|------|
| 读取 | 原生读取 `.txt`（UTF-8） | 纯文本，无需解析 |
| 切片 | 句子/段落感知切片 | 600 字符窗口 + 100 重叠，从句子边界切，不拦腰截断 |
| 向量化 | `BAAI/bge-small-zh-v1.5` | 本地中文 Embedding，离线可用（约 92 MB）；查询端加 bge 检索指令前缀 |
| 向量库 | Chroma | 本地持久化，增量 upsert，按 base_id 去重防孤儿片段 |
| 生成 | DeepSeek chat | OpenAI 兼容接口；超时/限流/错误均优雅降级 |
| 界面 | Streamlit | 网页问答 + 上传 |
| 重排 | `BAAI/bge-reranker-base` | 可选，默认关闭（见「消融矩阵」） |

## RAG 链路

```
文档(.txt) → 读取文本 → 句子感知切片 → bge 向量化 → Chroma 存储
                                          ↑
提问 → 加 bge 前缀向量检索 Top-K 片段 → 拼接[来源]上下文 → DeepSeek 生成答案（带引用）
```

## 数据说明

同一份 **Python 官方教程（tutorial 章节）** 提供两个语言版本，章节一一对应、文件名完全一致，用于对照实验：

| DOCSET | 目录 | collection | 文档数 | 片段数 | 说明 |
|---|---|---|---|---|---|
| `zh`（默认） | `docs_zh/tutorial/` | `documents_zh` | 17 | 267 | 官方简体中文版，由 `tools/fetch_docs_zh.py` 抓取生成 |
| `en` | `docs/tutorial/` | `documents` | 17 | 522 | 官方英文原版（Plain Text） |

切换方式：

```bash
set DOCSET=en      # Windows CMD
$env:DOCSET="en"   # PowerShell
export DOCSET=en   # bash
```

两套库写入不同 collection，互不覆盖，可用同一套评测样本直接做 A/B。

> **切换后必须重建对应库**：新的 collection 在首次访问时会被自动创建为空集合，此时问答会提示「知识库还是空的」。
> 到侧边栏点一次「建立 / 刷新预置知识库」即可，中文库约 33 秒。

选用纯文本而非 HTML/PDF：更稳定、体积更小、免去解析步骤（中文版仅在抓取阶段做一次 HTML→文本转换）。

## 运行步骤

1. 安装依赖（建议使用虚拟环境）：
   ```bash
   pip install -r requirements.txt
   ```
2. 配置 DeepSeek Key：复制 `.env.example` 为 `.env`，填入 `DEEPSEEK_API_KEY`。
3. 启动应用（Windows 可直接双击 `run.bat`）：
   ```bash
   streamlit run app.py
   ```
4. 在侧边栏点击「建立 / 刷新预置知识库」（首次会下载约 92 MB 中文向量模型，走 hf-mirror 镜像）。
5. 在输入框提问，例如「类和对象怎么定义？」「怎么读写文件？」「怎么处理异常？」

> 首次提问会有 10–30 秒等待：bge 模型在这一刻才加载进内存。之后单次检索约 22 毫秒。

## 检索评测（不依赖大模型）

```bash
python eval.py                    # 正样本命中率 + 负样本拒答率
python eval.py --calibrate        # 打印每题 top1 距离，用来说明"阈值不可分"
python eval.py --rerank           # 开启重排实验（默认关闭）
python eval.py --expand           # 开启查询扩展 + RRF 融合（默认关闭）
```

正样本见 `GOLD`（问题 → 可接受的章节名，多标签）；负样本见 `NEGATIVE`（答案不在文档里的问题，正确行为是拒答）。

### 核心结论：语料语言与向量模型对齐后，检索质量显著提升

同一套 10 正 + 10 负样本、同一个 `bge-small-zh-v1.5`、同一套切片参数，**只改变语料语言**：

| 指标 | 英文库（522 片段） | 中文库（267 片段） | 变化 |
|---|---|---|---|
| hit@5 | 100% | 100% | — |
| hit@1 | 70% | **90%** | **+20pt** |
| MRR | 0.833 | **0.920** | +0.087 |
| top1 距离中位数 | 1.007 | **0.806** | −0.201 |
| 拒答率 | 100% | 100% | — |
| 误拒率 | 0% | 0% | — |

**根因**：`bge-small-zh-v1.5` 是中文向量模型，用它编码英文 chunk 属于跨语言借用，向量空间对不齐。换成中文语料后工具与数据同域，距离值整体下移约 0.2，排序质量随之提升。这也解释了为什么此前 hit@5 能到 100% 但 hit@1 只有 70%——**召回没问题，是排序错位**。

### 完整消融矩阵

| 配置 | hit@1 | MRR | 单次检索延迟 |
|---|---|---|---|
| 英文库（单路） | 70% | 0.833 | 22 ms |
| 英文库 + 重排 | 50% | 0.637 | 5.8 s |
| 中文库（单路） | 90% | 0.920 | 22 ms |
| **中文库 + 重排** | **100%** | **1.000** | 5.8 s |
| 中文库 + 查询扩展 | 80% | 0.875 | 依赖 LLM |

两条优化手段的命运完全相反，原因都是「模型与语料是否同语言」：

1. **重排：英文库有害，中文库有益。** `bge-reranker-base` 是单语重排器，跨语言打分不可靠，会把正确结果挤下去（hit@1 70%→50%）；语言对齐后它恢复正常能力，把粗排漏排的正确片段提上来（90%→100%）。**同一个组件、同一份代码，只因语料语言不同，结论从 −20pt 翻转为 +10pt。**
2. **查询扩展：中文库下失效。** 该模块的设计目标是"把中文问题翻译成英文再检索"，用于弥补跨语言错位；中文语料下翻译分支失去意义，剩余的同义扩展只会稀释原始意图（90%→80%）。

### 默认配置的取舍

最终默认：**中文库 + 单路检索，重排关闭**。

| 选项 | 精度 | 延迟 | 决定 |
|---|---|---|---|
| 重排开 | hit@1 100% | 5.8 s | 交互式问答不可接受 |
| 重排关 | hit@1 90% | 22 ms | **采用** |

代价是牺牲 10pt 命中率，换来 265 倍的延迟改善。重排作为可选路径保留（`--rerank`），对精度敏感、允许秒级等待的离线批处理场景可以开启。**精度不是唯一指标，延迟同样是产品约束。**

### 拒答是怎么做的（含一次失败尝试）

1. **先试了距离阈值**：以为"top1 距离过大就拒答"。实测（中文库）正样本 top1 距离 0.702–0.999（中位 0.806）、负样本 0.705–1.132（中位 0.817），**两组几乎完全重叠**：距离最小的负样本 0.705，比距离最大的正样本 0.999 还近。阈值法不可分，弃用。证据可用 `--calibrate` 复现。
2. **改用词面兜底**：问题里的英文/专有名词（Redis、Django、MySQL…）在 top-k 片段中一个都没出现 → 判为库外，直接拒答、不调用模型。
3. **模型层语义拒答**：词面兜底只覆盖"带专有名词"的库外问题；纯中文的库外问题（如「红烧肉怎么做」「今天成都天气怎么样？」）靠 prompt 里"片段无对应信息就只回一句「文档中未找到相关信息」"来拦。实测三类问题均被正确拒绝：

| 问题类型 | 拦截层 | 输出 | 来源 |
|---|---|---|---|
| `怎么用 Python 连接 Redis 缓存？` | 词面兜底（不调模型） | `文档中未找到相关信息。` | 空 |
| `红烧肉怎么做？` | 模型语义判断 | `文档中未找到相关信息。` | 空 |
| `今天成都天气怎么样？` | 模型语义判断 | `文档中未找到相关信息。` | 空 |

> 修过一个坑：模型拒答后，代码仍把 top-k 片段当成"依据的文件"返回（真实复现：拒答 + 4 个无关来源）。改法是在 `rag.answer()` 出口统一识别拒答标记，归一化话术并清空 `sources`——**拒答是产品行为，不能让"检索到了什么"泄漏成"依据了什么"**。

### 一次完整的排查过程：重排为什么先失败、后又生效

`BAAI/bge-reranker-base`（CrossEncoder，粗排 20 → 重排取 5）上线过程有两轮完全相反的结论。

**第一轮（英文语料）——反而变差**：

| 指标 | 无重排 | 开重排 |
|---|---|---|
| hit@5 | 100% | 90% |
| hit@1 | **70%** | 50% |
| MRR | **0.833** | 0.637 |

初判原因是"跨语言打分不可靠"，于是**关闭重排**。但当时只解释了现象，没有隔离变量——真正被动的是两个因素：语料语言、重排器能力。

**第二轮（换成中文语料）——翻转为正向**：

| 指标 | 无重排 | 开重排 |
|---|---|---|
| hit@5 | 100% | 100% |
| hit@1 | 90% | **100%** |
| MRR | 0.920 | **1.000** |

同一份重排代码、同一个模型，只因语料从英文换成中文，结论从 −20pt 翻转为 +10pt。**说明第一轮的失败不是重排器不行，而是语料与模型不同语言。**

**但最终仍未默认上线**：重排把单次检索从 22 ms 推到 5.8 s（CPU 上 CrossEncoder 要跑 20 个 query-doc 对），交互式问答体验不可接受。作为可选路径保留（`--rerank`）。

> 这段经历的价值不在"我加了 rerank"，而在：一次失败结论不能只看单一变量。**先隔离变量再下判断，否则会把"用错了"错判成"不好用"。**

### 评测口径的修正

- 先前用**子串包含**匹配来源（`"stdlib" in "tutorial/stdlib2.txt"` 为真），会把 `stdlib2` 误判成 `stdlib` 命中，指标虚高。现改为**按文件名精确比对**。
- 先前用**单标签**标注（`命令行参数 → interpreter`），但该问题在中文版的章节归属不同：中文版 interpreter 的那节译作「传入参数」，而叫「命令行参数」的整节在 `stdlib.txt`（argparse）。单标签把「标注歧义」误判成「检索失败」。现改为**多标签，任一命中即算对**。

> 这两个坑说明：做多语料对照实验时，评测集本身也需要跨语言校验，否则测出来的是标注差异而不是系统差异。

### 评测的已知短板

样本仅 10 正 + 10 负，指标没有统计意义——它验证的是**评测流水线跑通**，不是系统真实水平。要做可信结论，样本量需上百条，并覆盖同义改写、多跳问题、长尾问题。当前也**只评了检索，未评生成质量**。

## 目录结构

```
python-doc-rag/
├── app.py              # Streamlit 界面
├── build.py            # 命令行重建知识库（打印片段数）
├── eval.py             # 评测：hit@K + 负样本拒答率（不依赖大模型）
├── requirements.txt
├── .env.example        # 复制为 .env 并填 Key（.env 不入库）
├── .gitignore          # 忽略 venv / db / *.log / .env / .idea 等
├── docs/tutorial/      # 英文语料：Python 官方教程 17 个 .txt（DOCSET=en）
├── docs_zh/tutorial/   # 中文语料：官方中文版 17 个 .txt（DOCSET=zh，默认）
├── tools/
│   └── fetch_docs_zh.py  # 抓取官方中文教程 HTML → 纯文本
├── src/
│   ├── config.py       # 路径与模型配置（DOCSET 切换语料，PRESET_DOCS_DIR 可覆盖）
│   ├── chunk.py        # 句子感知切片（600 窗口 + 100 重叠）
│   ├── embed.py        # Embedding 单例 + 查询端 bge 检索前缀
│   ├── ingest.py       # 文档读取入库（.txt，预置 + 上传，失败跳过）
│   ├── retriever.py    # 向量检索（单路 / 多路融合）
│   ├── rerank.py       # CrossEncoder 重排（可选，默认关闭）
│   ├── query_expand.py # 查询扩展（跨语言场景用，默认关闭）
│   ├── fusion.py       # RRF 多路结果融合
│   ├── generator.py    # DeepSeek 生成（带引用 + 异常兜底）
│   └── rag.py          # 主流程：检索 -> 库外判定 -> 生成 -> 拒答归一化
└── db/                 # Chroma 持久化向量库（不入库）
```

> 注：`venv / db / *.log / .env / .idea` 等已在 `.gitignore` 中忽略，不会进入版本库。
